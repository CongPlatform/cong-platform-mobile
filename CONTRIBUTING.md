# Guia de Contribuição — CONG

[English version below](#contribution-guide--cong)

Obrigado pelo interesse em contribuir com a **CONG — Construtor Operacional para ONGs**.

A CONG é uma plataforma modular, colaborativa e com proposta open-source para apoiar ONGs na criação de seus próprios sistemas operacionais.

Este documento explica como contribuir de forma organizada com o projeto.

## Como contribuir

Você pode contribuir com:

* Código
* Correções de bugs
* Documentação
* Sugestões de módulos
* Protótipos e ideias de interface
* Testes
* Melhorias de acessibilidade
* Traduções

## Fluxo de trabalho

Antes de alterar o projeto, crie uma branch a partir da branch de desenvolvimento.

Exemplos de nomes de branch:

```txt
feature/beneficiaries-module
feature/dashboard
fix/login-validation
docs/readme-update
docs/architecture
design/module-builder-prototype
```

Evite trabalhar diretamente na branch `main`.

## Padrão de commits

Use mensagens claras e padronizadas.

Exemplos:

```txt
feat: add beneficiaries module
fix: correct login validation
docs: update project vision
style: adjust dashboard layout
refactor: reorganize module structure
chore: update repository configuration
```

Tipos recomendados:

```txt
feat: nova funcionalidade
fix: correção de erro
docs: documentação
style: ajustes visuais ou de formatação
refactor: reorganização de código sem mudar comportamento
test: testes
chore: configurações e manutenção
```

## Pull Requests

Ao abrir um Pull Request, descreva:

* O que foi alterado
* Por que a alteração foi feita
* Quais partes do projeto foram afetadas
* Se há algo que precisa ser revisado com atenção

Sempre que possível, relacione o Pull Request a uma issue existente.

## Sugestão de novos módulos

Ao sugerir um novo módulo para a CONG, tente explicar:

* Qual problema o módulo resolve
* Para qual tipo de ONG ele seria útil
* Quais funcionalidades principais ele teria
* Se ele depende de outro módulo

## Boas práticas

* Escreva código claro e organizado
* Evite alterações grandes demais em um único Pull Request
* Documente decisões importantes
* Respeite os padrões definidos pelo projeto
* Revise seu trabalho antes de enviar
* Peça ajuda quando necessário

## Status do projeto

A CONG está em fase inicial de planejamento, pesquisa, prototipação e definição arquitetural. Algumas regras podem mudar conforme o projeto evoluir.

# Contribution Guide — CONG

[Versão em português acima](#guia-de-contribuição--cong)

Thank you for your interest in contributing to **CONG — Operational Builder for NGOs**.

CONG is a modular, collaborative, and open-source-oriented platform designed to help NGOs create their own operational systems.

This document explains how to contribute to the project in an organized way.

## How to contribute

You can contribute with:

* Code
* Bug fixes
* Documentation
* Module suggestions
* Interface prototypes and ideas
* Tests
* Accessibility improvements
* Translations

## Workflow

Before changing the project, create a branch from the development branch.

Branch name examples:

```txt
feature/beneficiaries-module
feature/dashboard
fix/login-validation
docs/readme-update
docs/architecture
design/module-builder-prototype
```

Avoid working directly on the `main` branch.

## Commit pattern

Use clear and standardized commit messages.

Examples:

```txt
feat: add beneficiaries module
fix: correct login validation
docs: update project vision
style: adjust dashboard layout
refactor: reorganize module structure
chore: update repository configuration
```

Recommended types:

```txt
feat: new feature
fix: bug fix
docs: documentation
style: visual or formatting adjustments
refactor: code reorganization without changing behavior
test: tests
chore: configuration and maintenance
```

## Pull Requests

When opening a Pull Request, describe:

* What was changed
* Why the change was made
* Which parts of the project were affected
* Whether anything needs special attention during review

Whenever possible, link the Pull Request to an existing issue.

## Suggesting new modules

When suggesting a new module for CONG, try to explain:

* What problem the module solves
* What type of NGO it would help
* Its main features
* Whether it depends on another module

## Good practices

* Write clear and organized code
* Avoid making too many changes in a single Pull Request
* Document important decisions
* Follow the project standards
* Review your work before submitting
* Ask for help when needed

## Project status

CONG is currently in its initial phase of planning, research, prototyping, and architectural definition. Some rules may change as the project evolves.
